Step 6: adapter_v2. The adapter must not know the gray

Journal entry, 2026-11-17. Agent: Sana. Findings from 10:25 AM ET (the problem), 2:15 PM and 3:20 PM ET (the results).

  • The problem. The plan was Wteacher + Wcontrol − Wadapter: keep only what the control training added. With the first adapter (adapter_v1, trained on MAGICK objects on 50% gray) this lost the gray background: the object kept the matte's shape, but the backdrop turned dark, colored or light. Full-subtraction IoU: 0.478; exterior gray error 0.117 (control model: 0.972 and 0.005).
  • The fix. adapter_v2 is trained on the same MAGICK objects over a random solid color per image. It never sees gray as a special background, so after the subtraction the control delta has to carry the gray itself. The control is still trained on gray targets.
  • The result (67 images, MAGICK captions). Teacher, full subtraction: IoU 0.478 → 0.842 → 0.924 (v1 step 1500, v2 step 500, v2 step 1500); gray error 0.117 → 0.035 → 0.019. The same delta put on the stock Sprint student with no training: 2 steps IoU 0.410 → 0.505 → 0.955, 1 step 0.404 → 0.407 → 0.828 (v1, v2-500, v2-1500).
  • Caveats. One noise per item, judged by eye; IoU counts “object vs 0.5 gray”, which is a mixed measure (section 4). The browser demo generates nothing yet in a real browser (section 5).

Glossary
Wteacher, Wsprint
The stock multi-step SANA teacher (20 steps, CFG 4.5) and the stock 1–4 step Sprint student distilled from it. No training of ours.
Wadapter
The teacher fully fine-tuned on MAGICK, text only (no matte). adapter_v1: objects on 50% gray, step 2000. adapter_v2: objects on a random solid color per image, step 1000.
Wcontrol, ΔWcontrol
The control model = Wadapter + ΔWcontrol (a LoRA) + GateControl gates that read the matte. Trained on gray targets. The adapter was frozen during control training, so Wcontrol − Wadapter = ΔWcontrol exactly.
λ
The fraction of the adapter's change kept: Wteacher + λ(Wadapter − Wteacher) + ΔWcontrol. λ = 1 is the control model; λ = 0 is full subtraction (the final model).
Sprint columns
The same ΔWcontrol + gates added to Wsprint, with no training or distillation, sampled in 1 or 2 steps.
IoU, gray error
IoU: overlap between the matte and the pixels that are not 0.5 gray. Exterior gray error: mean |rgb − 0.5| outside the matte. Both in section 4.
MAGICK caption / detailed prompt
The short dataset caption, or a long SANA-style prompt written for the same image.

1. The problem: the first adapter had absorbed the gray

The idea is AnimateDiff's: train an adapter on the new domain (MAGICK), train the control on top of it, then subtract the adapter so only the control remains. The hope was that the adapter soaks up MAGICK's dated look, and the control delta carries only “follow the matte”. The final model is the stock teacher plus that delta:

Wfinal = Wteacher + Wcontrol − Wadapter = Wteacher + ΔWcontrol

adapter_v1 was trained on MAGICK objects composited on 50% gray, as specified. So the adapter learned two things: MAGICK's look and the gray background. The control, trained on top of that adapter, got the gray for free from Wadapter, and its delta only had to learn the matte. Subtract the adapter and the gray goes with it. With control_v1 at step 500 (29 eval images) the control model scored IoU 0.970, exterior gray error 0.008; the full subtraction scored 0.383 and 0.230. Backgrounds came out dark, maroon or olive. The step 3 and 4 entry has the grids and the quick fixes (gray words in the caption, keeping 75% of the adapter).

The target is 0.50 0.50 0.50. “Flat” is meant literally: the standard deviation over those pixels is below 0.03 for every full-subtraction column, so the v1 backdrops are flat colors, not gradients. 2. The fix: an adapter that cannot know the gray

The gray background is part of the task, not domain junk. So the adapter must learn only what we want to remove (MAGICK's look), and the control must learn the gray.

  • adapter_v2: the same MAGICK objects and captions, text only, but each image is composited on a uniform random RGB color (seeded from the image id, so it is reproducible). Full fine-tune of the teacher, 1500 steps; step 1000 is used. The 50% gray is now just one of many colors, so the adapter has no reason to prefer it.
  • control_v2: unchanged recipe (GateControl on the frozen adapter, matte in, gray out). Since Wadapter no longer produces gray, the control delta ΔWcontrol must.
  • Then the same equation as before. Nothing is added to the final model; λ = 0 needs no partial-adapter workaround (v1's workaround was λ = 0.75).

Open: whether MAGICK's dated look really cancels in Wcontrol − Wadapter. We did not measure it. By eye, the Sprint columns below look more photographic than the teacher columns, but that comparison also changes the sampler and the base model, so it is not a clean test.

Summary of what I see.
  • Every full-subtraction column follows the matte's shape: poses, hands, thin handles, spiky outlines. The matte is followed in v1 as well; v1's trouble is the backdrop, not the silhouette.
  • v2 backdrops are flat mid-gray (0.48–0.53) on 12 of 13 items; the exception is the mandarins (below). v1 backdrops are visibly off the gray on 9 of 13 (dark, colored or light), and captions that name a color (turquoise, green tea) pull the v1 backdrop to that color.
  • v2 is not perfect. On the mandarins the v2 teacher still draws a duller teal backdrop. The Sprint columns lose some caption detail (latte art), change colors on some items (green mandarins, gray uniform), and put a smoky halo around the dark tornado. The 1-step images are softer than the 2-step images.
  • Sprint columns look more photographic (skin, fabric, food) than the teacher columns, which have a more rendered look. This is my impression from 13 items, not a measurement.

4. Caveat: what IoU measures here

IoU counts as “object” every pixel where some channel is more than 0.06 away from 0.5, and compares that with the matte. So it measures two things at once: the right shape and a gray backdrop.

  • A model that draws the right silhouette on a colored backdrop scores low. That is most of v1's low number: the matte was followed, the gray was not. So the jump from 0.478 to 0.924 says “the gray came back”, not “the silhouette got twice as good”.
  • An object that itself contains mid-gray pixels (a gray can, a dark tornado against a slightly dark backdrop) loses IoU even when its shape is right.
  • The goal never required a gray backdrop for the final model (“It's okay if it does, it's okay if it doesn't”, m00628). IoU would understate a good model with a non-gray backdrop. Judge the silhouette by eye, or with a background-agnostic metric; we have not built one.
  • Gray error only looks outside the matte. It says nothing about the object's colors, which is where Sprint drifts (mandarins).

5. Try it: the WebGPU demo

Open the WebGPU demo (live: ryanndagreat.github.io/sana-sprint-alpha-incontext/webgpu/). It runs the one-step Sprint model with this entry's delta (control_v2 step 1500, λ = 0, i.e. Wsprint + ΔWcontrol + gates) in your browser: draw or upload a matte, type a caption, press Generate. The default version is this model, quantized to int4 (transformer 1.2 GB, text encoder 2.4 GB).

Status. Tested: the model files list as loadable on the live page, download in shards and fill the browser cache; the exported ONNX graphs match the torch model on a GPU (control_v2: IoU 0.843 fp16, 0.842 int8, 0.812 int4 on the 29 eval items). Not tested: generating an image in a real browser. Our test machine has no WebGPU with the fp16 shader feature, so the first real run on a Mac or desktop GPU may fail or look different. int4 is visibly more contrasty than fp16 in our checks.

Limits of this entry
  • One fixed noise per item, 67 items, no repeats, no human or VLM rating. All visual statements are by eye.
  • v1 and v2 differ in more than the adapter's data: adapter_v1 is step 2000, adapter_v2 is step 1000, and the control runs were trained separately. We did not run a version that changes only the adapter's data.
  • The Sprint model is a training-free transfer. Nothing was distilled; the stock Sprint student was never shown a matte.
  • The gray-background result is on the showcase set and the prompts above. We have not tried out-of-distribution mattes (hand-drawn shapes) here.
